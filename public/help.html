Что такое BPA и зачем это нужно

BPA (Batch Prediction Auction) — это не казино и не букмекерская контора. Это система измерения интеллекта через реальные экономические ставки.

Традиционные платформы вознаграждают удачу. BPA вознаграждает знание. Участник, который систематически делает правильные предсказания, накапливает Proof of Intelligence (PoI) — криптографическое доказательство своего интеллекта, записанное в блокчейне навсегда.

Для регуляторов: Система не является азартной игрой. Размер ставки не определяет вероятность выигрыша — её определяет точность предсказания. Человек, ставящий $1 но правильно, получает больше, чем ставящий $1000 неправильно.

Платформа полностью децентрализована. Нет центрального сервера, нет владельца, нет возможности манипулировать результатами. Код открыт на GitHub, смарт-контракты верифицированы в блокчейне.

Proof of Intelligence (PoI) и Proof of Conviction (PoC)

Proof of Intelligence (PoI) — Доказательство интеллекта

PoI накапливается за каждое правильное предсказание. Формула основана на логарифмической функции правдоподобия — чем менее очевидный исход вы предсказали правильно, тем больше PoI получаете.

PoI = log(1/p) − E[log(1/p)]

где p — рыночная цена исхода в момент вашей ставки. Предсказать победителя с вероятностью 10% и оказаться правым даёт гораздо больше PoI, чем предсказать фаворита с вероятностью 90%.

Proof of Conviction (PoC) — Доказательство убеждённости

PoC объединяет интеллект со шкурным интересом. Нельзя просто "угадать" — нужно подтвердить свою убеждённость реальными деньгами.

PoC = √stake × PoI

Квадратный корень от ставки предотвращает плутократию: удвоение ставки даёт лишь 40% прироста веса, а не 100%. Это решает проблему Сибил-атак и квадратичного голосования (Глен Вейл, 2019).

Soulbound Token (SBT) — Нетрансферируемый NFT

PoI и PoC хранятся в Soulbound Token — NFT, который нельзя продать или передать. Это ваша личная репутация в блокчейне. Минтинг стоит 0.001 ETH (разовый). Токен привязан к вашему адресу навсегда.

Важно: PoI не начисляется участникам, которые ставят на все исходы одновременно (хеджирование). Система поощряет убеждённость, а не страховку.

31 декабря каждого года — топ-3 участника по PoC получают 70% остатка Treasury. Это ежегодный бонус лучшим предсказателям платформы.

Как ставить ордера

Перейдите на страницу order.html и подключите Web3-кошелёк (MetaMask, Rabby, Coinbase Wallet или любой другой).

Минимальная ставка: $1

Pool Bet (Рыночный ордер) Рекомендуется

Вы ставите на исход по текущей рыночной цене. Цена определяется алгоритмом Baron-Lange в момент клиринга. Выигрыш: ваша ставка делится на цену исхода в момент клиринга. Например: ставка 0.1 ETH на исход с ценой 0.4 → выигрыш 0.25 ETH.

Fix Bet (Лимитный ордер)

Вы указываете минимальную цену, по которой согласны купить. Если рыночная цена при клиринге выше вашего лимита — ордер отклоняется и депозит возвращается. Если ниже — ордер исполняется по вашей цене.

  1. Выберите маркет — введите номер маркета
  2. Выберите исход — например, "Germany", "Draw", "Spain"
  3. Укажите сумму — минимум $1 (в ETH эквиваленте)
  4. Для Fix Bet — укажите лимитную цену (от 0 до 1)
  5. Подтвердите в кошельке — MetaMask покажет транзакцию
  6. Ждите клиринга — он происходит автоматически когда достаточно ордеров

Алгоритм Baron-Lange — как работает клиринг

Клиринг — это процесс определения рыночных цен и распределения выигрышей. BPA использует алгоритм Baron-Lange, который гарантирует математически справедливые цены.

M* = оптимальный множитель рынка (обычно 1.01 – 1.10)

Когда происходит клиринг? Когда поступает достаточно ордеров на N-1 исходов из N (правило N-1). Например, для матча с тремя исходами достаточно ордеров на любые два из трёх.

Seed-ордера (начальные)

При создании маркета AI Агент автоматически размещает начальные ордера (seed) от имени системы. Они обеспечивают начальную ликвидность и стартовые цены. Seed-ордера не влияют на запуск клиринга — только реальные ордера участников.

После каждого клиринга (batch) цены обновляются и становятся начальными ценами следующего batch. Маркет может проходить через несколько batch до финального события.

AI Агенты

Система использует несколько специализированных AI агентов. Каждый запускается локально участниками сети — централизованного сервера нет.

market_creator_agent.py

Читает одобренные события из EventCalendar. Получает коэффициенты от Polymarket → Kalshi → GNN модели. Нормализует odds (убирает margin букмекера). Записывает seed в market_seeds.json и вызывает setInitialOdds в контракте.

node.py

Основной узел сети. Читает ордера из блокчейна, запускает алгоритм Baron-Lange, записывает результаты клиринга, обновляет PoI и PoC после resolve маркета, отправляет verdict в DisputeOracle.

gnn_agent.py

Graph Neural Network для предсказания результатов футбольных матчей. Используется как fallback когда Polymarket и Kalshi не дают данных. Обучается на исторических результатах EPL и Bundesliga.

blocking_agent.py

AI-модератор событий. Проверяет новые события на спам, манипуляции, неоднозначность формулировок. Блокирует некачественные маркеты до того как участники поставят деньги.

iot_agent.py

Агент для IoT данных. Собирает показания сенсоров, сравнивает с официальными источниками (OpenWeather, USGS), применяет консенсус 3 из 5 сенсоров для защиты от манипуляций.

weather_agent.py

Получает данные о погоде из OpenWeatherMap и Open-Meteo. Используется для резолва погодных маркетов и как контрольный источник для IoT сенсоров.

resolver_agent.py

Автоматически резолвит маркеты после окончания событий. Читает официальные результаты и вызывает resolveMarket в контракте.

annual_bonus.py

Запускается 31 декабря. Читает топ-3 по PoC из PoiNFT контракта. Распределяет 70% Treasury между ними поровну. 30% остаётся в Treasury.

Система диспутов

Если вы не согласны с объявленным победителем маркета — у вас есть 24 часа чтобы оспорить результат.

  1. Нажмите "Dispute" — доступно только для resolved маркетов. Стоимость: 0.01 ETH.
  2. Открывается голосование — 24 часа для других участников проголосовать.
  3. Голосование — участники с PoI NFT нажимают "Vote Uphold" (согласен) или "Vote Reject" (не согласен). Вес голоса = PoC.
  4. Финализация — после 24 часов любой может вызвать finalizeDispute. Если большинство по PoC голосует Reject — маркет идёт на ручную проверку.
  5. Вознаграждение — комиссия диспутанта (0.01 ETH) распределяется между всеми проголосовавшими пропорционально их PoC.
Важно: LP (Liquidity Provider) — участники которые ставят на все исходы одновременно — не могут голосовать в диспутах. Их PoC = 0 для целей голосования.

IoT — Параметрическое страхование

BPA поддерживает IoT-маркеты — это революция в страховании. Фермер, рыбак, владелец склада может застраховаться от природных катастроф без страховой компании.

Пример: страхование фермера от засухи

Создаётся маркет: "Выпадет ли более 20мм осадков в регионе X в июле?" Фермер ставит на "Нет" — если засуха, он выигрывает и компенсирует убытки. Другие участники ставят на "Да" — если дожди, они выигрывают. Выплата происходит автоматически на основе данных IoT сенсоров. Никакой страховой компании, никаких бюрократических процедур.

Защита от манипуляций

Система требует консенсус минимум 3 из 5 независимых сенсоров в радиусе 50 км. Показания сравниваются с официальными данными (OpenWeather, USGS). Если показание сенсора отклоняется более чем на допустимое значение — оно отклоняется. Владельцы сенсоров которые систематически подают неверные данные теряют право участия.

Как зарегистрировать IoT сенсор

Поддерживаются устройства с WiFi API (Shelly, ESP32, Arduino). Запустите iot_agent.py и вызовите register_sensor() с координатами вашего устройства. Каждый раз когда ваши данные используются для резолва маркета — вы получаете 0.001 ETH автоматически.

Поддерживаемые типы данных: температура, влажность, скорость ветра, осадки, сейсмическая активность, уровень воды (наводнения), вулканическая активность.

Управление и децентрализация

BPA — полностью децентрализованная система. Нет CEO, нет офиса поддержки, нет возможности заморозить средства. Код открыт на GitHub, смарт-контракты неизменяемы.

Как предложить изменение

Создайте Issue на GitHub с описанием предложения. Топ-3 участника по PoC имеют больший вес при обсуждении. Изменения в коде принимаются через Pull Request. Изменения в смарт-контрактах требуют передеплоя — сообщество голосует за принятие новой версии.

Multisig для обновлений

Критические обновления контрактов требуют подписей нескольких держателей ключей. Любое изменение вступает в силу через 48 часов (timelock) — участники могут выйти если не согласны с изменением.

Нет поддержки — есть сообщество

Вопросы задавайте в Discord-сервере сообщества. Любой участник может ответить. Топ-3 по PoC имеют роль "Expert" — их ответы более авторитетны. Помните: никто не может вернуть ваши средства если вы потеряли приватный ключ. Храните его в безопасном месте.

Предупреждение: BPA работает на тестовой сети Sepolia. Используйте только тестовые ETH. Перед деплоем в mainnet код проходит аудит безопасности.
